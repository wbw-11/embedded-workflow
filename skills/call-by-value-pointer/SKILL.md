# 传值调用与传指针：函数参数方向设计

## R — 原文 (Reading)

> "在C语言中，所有函数参数都是'通过值'传递的。也就是说，传递给被调用函数的参数值存放在临时变量中，而不是存放在原来的变量中。被调用函数不能直接修改主调函数中变量的值，而只能修改其私有的临时副本的值。"（第1章 §1.8）
>
> "必要时…调用者需要向被调用函数提供待设置值的变量的地址。"（第1章 §1.8）
>
> "由于C语言是以传值的方式将参数值传递给被调用函数。因此，被调用函数不能直接修改主调函数中变量的值。例如…swap函数…如果将swap函数定义为void swap(int x, int y)…则swap(a, b); 无法达到交换a、b的目的。"（第5章 §5.2）
>
> — B. W. Kernighan & D. M. Ritchie, 第1章 §1.8 / 第5章 §5.2

---

## I — 方法论骨架 (Interpretation)

C 的参数传递只有一种模式：**按值拷贝**。被调函数拿到的形参是实参值的副本，对它任何修改都不会写回调用者。由此推出的决策规则：

- 函数只需要"读"实参的值 → 普通传值即可；
- 函数必须"改写"调用者的变量（输出参数）→ 必须传该变量的地址（指针），形参声明为指针，函数内经 `*ptr` 间接访问；
- 数组实参自动退化为首元素地址（数组名就是地址值），所以函数天然能改数组内容；
- 经典双通道模式：**返回值传状态/核心结果，指针参数回传次要结果**（如 getint 用返回值传是否成功、指针回传读到的数）。

这套"输入走值、输出走指针"的方向设计，是设计一切 C 函数签名前要先做的判断。

## A1 — 书中的应用 (Past Application)

### 案例 1: 失效的 swap
- **问题**: 排序交换函数第一次写成 `swap(int x, int y)`，`swap(a,b)` 后 a,b 没变。
- **方法论的使用**: 作者指出这是传值调用——x,y 只是 a,b 的副本，交换副本不影响原值。
- **结论**: "参数通过值传递…被调用函数不能直接修改主调函数中变量的值"。
- **结果**: 改为 `swap(int *px, int *py)`，调用 `swap(&a,&b)`，函数内 `temp=*px; *px=*py; *py=temp;` 达成目的（第5章 §5.2）。

### 案例 2: getint 双通道
- **问题**: 需要从输入流读一个整数，同时通知调用者"是否成功读到"。
- **方法论的使用**: 返回值传"读到/未读到"状态，把读到的数通过指针参数 `*pn` 写回。
- **结论**: "返回值传状态、指针回传数据"是 C 函数的惯用输出设计。
- **结果**: `int getint(int *pn)` 成为标准 I/O 输出模式样板（第5章 §5.2）。

### 案例 3: main 里数组首元素地址传参
- **问题**: 把数组交给函数处理。
- **方法论的使用**: 数组名本身是地址值，直接传名即传首元素地址，函数内可改原数组。
- **结论**: 这也是"传值调用"——传的是地址值本身，不是整个数组的拷贝。
- **结果**: 全书所有数组参数（getline/copy/strlen）都用此模式（第1章 §1.9）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 写函数后发现"形参改了但实参没变"，怀疑是不是 C 的传参方式问题；
2. 需要让一个函数返回多个值（两个数相除得商和余、读输入得值和状态），不知道签名怎么设计；
3. 写嵌入式驱动时函数需要把寄存器值写回调用者的局部变量；
4. 阅读/改写别人代码时看到 `&x` 传参或者 `int *` 形参，需要确认为什么这么写；
5. 混淆 `scanf("%d", &n)` 里为什么要取地址。

### 语言信号 (用户的话里出现这些就应激活)

- "为什么函数里改了，外面没变？"
- "怎么让函数返回两个值？"
- "swap 怎么写才对？"
- "为什么要传 & / 指针参数？"
- "call by value / pass by pointer / output parameter / 函数改不动实参"

### 与相邻 skill 的区分

- 与 `pointer-array` 的区别: 它管"下标↔指针算术换算"（表达式语义），本 skill 管"函数签名怎么定输入/输出方向"（接口设计）。
- 与 `undefined-behavior` 的区别: 传值错误通常是"功能不对"，未定义行为是"结果不可预期"，前者是设计失误、后者是语言契约违反。

## E — 可执行步骤 (Execution)

1. **判定每个参数是"读"还是"写/改"**
   - 完成标准: 分类清单——只读参数、写入参数、读写参数；写出每个读参数用值、写参数用指针。
   - 判停条件: 若参数是数组/结构体这类大对象且只读，考虑是否愿传指针以避免拷贝开销（注明这是优化取舍非正确性需求）。

2. **🔴 CHECKPOINT · 仅签名侧枝决策时确认**
   - 完成标准: 参数读/写分类清晰、不需要改既有调用点时，直接进入步骤 3，不打断用户。
   - 判停条件: 仅当设计涉及需改动调用点（新增 `&`/改签名会牵连多文件）或"要否为只读大对象传指针"这类优化取舍时，向用户确认是否接受签名/调用点修改，确认后再继续。

3. **设计签名并写调用点**
   - 完成标准: 写入参数声明为指针类型；调用点对该实参取地址 `&`（数组名除外）；漏 `&` 处圈出。
   - 判停条件: 需要多结果时，采用"返回值传状态 + 指针回传数据"双通道，并明确每个通道语义。

4. **🛑 STOP · 仅行为变化时确认**
   - 完成标准: 修正版与用户原写法语义一致（只是参数方向修正）时，直接给出结论。
   - 判停条件: 仅当改写会改变既有行为（如把传值改为传指针后函数会写回调用者变量、而用户没预期这种副作用）时暂停，明确告知"改写后调用者的 X 变量会被修改"，由用户决定是否接受。

5. **回验正确性**
   - 完成标准: 在调用点断言实参确实被修改；对"误以为传值能改实参"的写法指出具体错误并给出修正版。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户其实是在问传值语义下结构体/数组如何拷贝（那是 data-organization 讨论）；
- 对象是 C++ 引用/`std::move` 语义，与 C 传值不同；
- 用户需要的是宏参数传递行为（见 macro-vs-function）。

### 作者在书中警告的失败模式

- swap 传值反例（第5章 §5.2）：形参交换副本，实参不变；
- 隐式声明/原型不一致（第4章 §4.2）：跨文件函数返回类型不匹配导致垃圾结果（与 function-prototype 配合）；
- 对数组名做 `a=pa`、`a++` 等"以为数组名是变量"的误用（见 pointer-array）。

### 作者的盲点 / 时代局限

- 本书不讨论 C++ 引用的替代角色；现代实践可用 `restrict`/`const` 限定指针避免误改（书中未强调 const 的地位）。
- 多返回值设计在现代 C 也常用退出码 + errno 或输出 structure 聚合，书中以指针回传为主流。

### 容易混淆的邻近方法论

- `function-prototype`（声明怎么写）与本 skill（参数方向怎么定）——顺序上是先定方向再写声明；
- `pointer-array` 的指针算术与本 skill 的传地址——后者是前者在函数接口上的应用。

# 端侧 / 边缘 AI 开发工作流

端侧 AI 项目（自训模型部署到 MCU）与普通嵌入式开发有本质区别：**模型错误不报错、不告警**，特征域差之毫厘、输出谬以千里。本工作流沉淀自 KWS 唤醒词实战（特征对齐 5 大根因链），用于避免重走弯路。

## 一、启动检查：模型-硬件适配（写码前必做）

| 检查项 | 内容 | 判定 |
|---|---|---|
| 推理引擎 | 目标芯片可用引擎（esp-sr / tflite-micro / CMSIS-NN / NPU） | 官方预训练模型优先 |
| 硬件加速 | 量化（INT8）是否能走芯片专用核（esp_nn 汇编 / DSP） | 无加速时 M 级 MAC ≈ 100ms+ |
| 内存预算 | arena/中间张量内存（内部 RAM vs PSRAM）与堆预算 | 大 arena 放 PSRAM；PSRAM 上跑汇编算子可能崩 |
| 实时性预算 | 推理耗时 vs 帧周期（如唤醒 20ms）；主循环是否饿死 IDLE → WDT | 推理 > 周期必须增量/跳帧或缩模型 |
| 特征输入格式 | 训练时张量布局（如 (C,F) 与 (F,C)）| **最高频隐性 bug** |

**决策原则：先查官方成熟方案再自研**。官方 wakenet 3/3 分钟级命中 vs 自研全链路数小时攻坚——除非有明确理由（离线/自定义词汇/无官方模型），否则优先官方。

## 二、特征管线一致性清单（训练/自检/实时三端逐项核对）

AI 模型输出恒定/无响应时，先过此清单（每项都可能静默致残）：

- [ ] **预处理参数**：采样率 / 帧长 / hop / mel 数 / 系数数，三端一致
- [ ] **AmplitudeToDB / top_db**：训练（如 torchaudio 默认 `top_db=None`）与端侧实现必须一致——不一致会导致弱信号特征域背离、强信号（合成样本/自检）碰巧一致而假 PASS
- [ ] **张量布局**：训练输出形状（如 torchaudio MFCC → (40,46)）与端侧喂入形状必须一致（含轴顺序），**禁止用 reshape 替代转置**
- [ ] **去直流/归一化**：端侧 ADC 直流偏置（如 ES8311 -600~-1300）必须与训练数据对齐（减均值），否则低频特征整体偏移
- [ ] **窗口长度 >= 目标内容时长**：窗口必须完整容纳识别对象（唤醒词 1.2s → 窗口 ≥1.6s），否则"不响应"是正确行为
- [ ] **特征数值域比对**：用固定样本，端侧 dump 特征逐元素与 PC 对比（可容忍舍入精度差异）

## 三、双域验证三步法（部署验证标准流程，禁止跳级）

1. **PC 域**：训练集 + 真实采集数据，在 PC 上推理确认命中率（如滑窗 100% 命中）——先证明"模型 + 特征管线"正确
2. **端侧自检**：固定基准样本（合成/录制的稳定样本），端侧推理输出与 PC 基准比对（argmax 一致且数值接近）——证明"部署链路"正确。**注意 selfcheck 假 PASS 陷阱**：自检用与端侧同一错位路径时依然一致，必须搭配第 1、3 步才可信
3. **端侧真实信号**：实测唤醒/识别，logits 或得分应随真实输入显著变化（不响应 = 特征或性能问题，回查清单）

## 四、数据质量检查（训练前必查波形）

- [ ] 峰值是否接近满幅削波（如 int16 ±32767）——削波会把语音毁成方波谐波
- [ ] 平均幅值量级与真实端侧信号一致（端侧增益 30dB 削波 / 6dB 过弱 → 用波形能量校准）
- [ ] 过零率、直流偏置是否正常
- [ ] 训练样本的"域"与端侧实时采集一致（同一麦克风/增益/距离，不要 PC 麦克风混装）

## 五、推理性能工程

- 整窗重算 vs 增量更新：滑窗特征可用增量算法（每周期只算新帧 FFT/mel，O(1)），避免全窗重算超实时预算
- 主循环必须有让出 CPU 的路径（阻塞读/延时），否则 IDLE 饿死 → task_wdt 复位
- 推理耗时实测以"日志时间戳间隔"为准（如 dbg 间隔 >> 节流值即推理过慢）

## 六、端侧调试手段

- **dump 复现法（最有力）**：端侧将特征/PCM 以 hex 打印到串口 → PC 重建 → PC 复现推理对比端侧输出，一锤定音定位"端侧实现问题"还是"模型问题"
- dump 长行注意缓冲区上限（sprintf 溢出会崩溃）与看门狗（打印阻塞时间）
- 能量 / 峰值 / 过零等诊断指标打进循环日志，用于判断采集通路与数据质量

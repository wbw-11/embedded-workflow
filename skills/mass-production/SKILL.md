# 量产落地框架

消费电子项目从"样机调通"到"批量交付"的标准动作。**框架先行、实战后补**：流程与模板现在就能用；产测固件的逐产品适配等有真实产线项目再做。

## 一、量产烧录流程（三路径卡片）

| 路径 | 适用 | 关键步骤 |
|---|---|---|
| J-Flash / 批量烧录器 | 大产线 | 固定 hex 版本号 → 烧录 → 读回比对 → 首件 3 片全检 |
| 串口 ISP | 无调试器工位 | BOOT0 拉高 → ISP 协议烧录 → 校验 → BOOT0 恢复 |
| Keil/调试器 | 试产小批 | 与开发流程一致，烧录后必须验证运行 |

**首件校验铁律**：每批次首件读回 Flash 与 hex 逐字节比对 + 上电功能冒烟，通过才放行批次。

**序列号区规划**（烧录前置设计）：

- 在 Flash 尾部保留区（如最后 1KB）划分序列号/校准参数区
- 格式示例：`2字节年份 + 4字节流水号 + 2字节CRC`
- 序列号规则：唯一、可追踪、与生产日期批次挂钩
- 烧录工装写入后必须回读校验一次

## 二、产测自检固件（工位模式）

- 基于 peripheral-test-template 技能扩展"工位模式"：
  1. 上电全外设自检，串口逐项输出 `PASS/FAIL`
  2. 结束 LED/蜂鸣器长鸣指示（PASS 亮绿/短鸣，FAIL 亮红/长鸣）
  3. 日志首行带固件版本号和序列号
- 框架给固定结构（初始化→自检序列→结果上报），**具体每项自检按产品外设填写**
- 输出格式与 test-report 技能对齐，全检报告可自动生成

## 三、良品率台账（Excel 模板）

用表格工具（Excel/CSV）生成固定列：

| 列 | 内容 |
|---|---|
| 日期/批次/序列号 | 定位到片 |
| 不良现象 | 空口描述 |
| 初判责任 | 软件/硬件/装配/来料 |
| 定位过程 | 用了什么工具，卡在哪 |
| 对策 | 软件补丁/硬件整改/工艺调整 |
| 回归结果 | 验证批次与结论 |

台账规则：
- 同一现象累计 ≥3 片必须升级为专项分析
- 软件类不良对策必须回写进设计文档与固件版本说明

## 四、Release 构建配置（量产交付前置，交付固件必须用 Release 构建）

> Debug 构建带调试接口、详细日志、低优化，交付/量产一律禁止。
> 编译产物放行前逐项核对，未通过不发固件。

### 4.1 Keil ARM（GD32/STM32）

| 项 | Debug（开发） | Release（交付） |
|---|---|---|
| 优化等级 | -O0 | **-O2**（大项目内存紧张用 -Os） |
| 半主机 | 可用 | **关闭**（脱机跑依赖半主机会死机） |
| 调试打印 | 全开 | **DEBUG 宏控制**：`#define DEBUG 0` 时 printf 输出为空宏 |
| 看门狗 | 未启用 | **启用**（7×24 运行产品必须） |
| Flash 读保护 | 关闭 | **开启 RDP Level 1**（GD32 FMC_OB / STM32 FLASH_OB） |
| SWD 接口 | 全功能 | **密码保护或复用为 GPIO**（视产品是否需要现场升级） |

### 4.2 STC8/8051（Keil C51）

| 项 | Debug | Release |
|---|---|---|
| 优化等级 | 0 | **8 或 9**（实测后确认哪个稳） |
| 调试打印 | 全开 | **DEBUG 宏关闭**（8051 串口打印极耗时间） |
| STC 加密 | 不设置 | **STC-ISP 勾选加密**（程序加密后传输 + ID 号加密可选） |

### 4.3 ESP-IDF（menuconfig）

| 项 | Debug | Release |
|---|---|---|
| 日志级别 | CONFIG_LOG_DEFAULT_LEVEL_DEBUG | **CONFIG_LOG_DEFAULT_LEVEL_WARN**（或 ERROR） |
| Core Dump | 任意 | **CONFIG_ESP_COREDUMP_ENABLE_TO_NONE** |
| 断言 | ESP32_ASSERT_PRINT | **禁用或仅重启** |
| Flash 加密 | 关闭 | **Secure Boot + Flash Encryption**（带密钥的产品） |

### 4.4 Release 构建放行检查（发出固件前逐项过）

- [ ] 重启/上电 100 次无异常（Release 优化可能暴露 Debug 没有的时序问题）
- [ ] 用 Release 固件重跑脱机复验（Q10：拔调试器独立上电）
- [ ] 固件内版本号字符串存在（Keil: strings 查 FW_VERSION；ESP-IDF: esptool image_info）
- [ ] Debug 打印确认关闭（串口无调试日志刷屏）
- [ ] 读保护开启后回读 Flash 确认被拒（`Cannot access` / 全 0xFF）
- [ ] 产生固件的源码已 git tag（与版本号一致）

> **Debug/Release 差异铁律**：任何"Debug 能跑 Release 挂了"的问题，优先怀疑未初始化变量（-O2 下寄存器初值不同）、时序依赖（-O2 变快）、volatile 缺失。

## 六、阶段定位（诚实边界）

- **现在可做**：烧录流程卡片、序列号区规划、台账模板、产测骨架、Release 构建配置
- **量产项目时才做**：真实产测固件适配、批量一致性验证、SRRC 等认证配合
- 没有产线环境时不要预演量产细节，框架就绪即止

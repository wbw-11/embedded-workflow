# 嵌入式代码审查清单

## 概述

本清单用于审查嵌入式 C 语言代码，覆盖中断安全、内存安全（含数据溢出专项）、硬件配置、代码规范、低功耗、外设特定坑等关键维度。逐项检查，发现问题立即修正。

> **审查规则层级关系**：
> - **精华要点**（3条）：见 `project_memory.md` "嵌入式代码审查最佳实践"章节
> - **红线规则 + 工作流程**：见 `embedded-dev-rules` 技能（强制遵守的开发红线）
> - **完整审查清单**（本技能）：全量检查项，用于提交前逐项审查

**使用时机：**
- 完成一个功能模块后
- 提交代码前
- 用户要求审查代码时
- 修改 ISR 或驱动代码后

## 场景入口：按"修改了什么代码"选轻量化清单（P0 推荐）

> **原则**：小改动不跑 20 章全量。**先跑脚本 → 再按场景人工补 8~15 项**，时间省 60%，漏检率反而更低（避免信息过载跳过关键项）。
>
> **检查项标识说明**：
> - `[A] 脚本自动扫` — 先跑 `code-style-check.ps1 -Checks overflow,defensive,brace,naming,header` 自动覆盖
> - `[M] 人工审查` — 脚本扫不出来，必须人眼 + 逻辑判断

---

### 场景 1：改了 ISR / 中断回调（USART/TIM/EXTI/DMA_IRQHandler 等）

**先跑脚本**：`code-style-check.ps1 -Checks overflow,defensive` → 自动覆盖 Q6（ISR 喂狗）、阻塞 sprintf/memcpy 越界、局部变量初始化

| 顺序 | 检查项 | 方式 | 为什么不能漏 |
|---|---|---|---|
| 1 | ISR 里无 `printf/sprintf/malloc/delay_ms/while(!flag)` 等阻塞或耗时操作 | [M] | ISR 超时 1ms 会阻塞高优先级中断，导致串口 Overrun / 通信掉包 |
| 2 | **Q6 看门狗喂狗位置**：ISR 内无 `iwdg_feed / fwdgt_counter_reload / wdt_feed` | [A] | 主循环死了中断还在喂 → 看门狗永远不触发，等于没开 |
| 3 | 中断标志位先处理数据后清除，清除的是 **int_flag 而非 stat_flag** | [M] | 先清标志再读数据 → 丢最后 1 字节；清错标志位 → 永远进中断 |
| 4 | ISR 中修改的全局变量加了 `volatile`；8 位 MCU 上 16/32 位有关中断保护 | [M] | 缺 volatile → 编译器优化后主循环读不到更新；非原子读 → 高低字节错位 |
| 5 | **Q7 抢占级顺序**：此 ISR 抢占级与项目一致（通信>定时>EXTI，分组 PRE2_SUB2 已写死 main 首行） | [A] 脚本自动检测 main() 中是否有 nvic_priority_group_set 调用 + [M] 抢占级数值顺序仍需人眼确认 | 默认 PRIGROUP_0 全 0 抢占级 → UART 收包被 EXTI 长消抖阻塞 Overrun |
| 6 | EXTI 按键 ISR 没做"立即执行动作"，只启动消抖定时器，20ms 后确认再响应 | [M] | 机械抖动 1 次按键触发 5~20 次 ISR → 功能乱跳 |
| 7 | 与主循环/任务的接口：只置 `volatile` 标志位/推入环形队列，不直接调用高层业务逻辑 | [M] | ISR 里直接跑业务 → 系统实时性崩；分层耦合破坏 |
| 8 | ISR 函数名与 startup/vector_table 一致（GD32F4 `USART0_IRQHandler` 不能写成 `USART0_IRQHandler1`） | [M] | 名字错 → 中断不进或进 Default_Handler 死循环 |
| 9 | FreeRTOS 项目中，高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的 ISR 没调 `FromISR` API | [M] | 高于阈值调 FromISR → FreeRTOS 临界区破坏 → 随机 HardFault |

### 场景 2：改了外设驱动（UART/SPI/I2C/ADC/定时器 init / read / write）

**先跑脚本**：`code-style-check.ps1 -Checks overflow,defensive,naming` → 自动覆盖不安全函数、长度写死、宏括号缺

| 顺序 | 检查项 | 方式 | 为什么不能漏 |
|---|---|---|---|
| 1 | 初始化顺序：**时钟 RCU 先开 → GPIO/AF 配置 → 外设 init → 中断使能**；外设寄存器读写前时钟已开 | [M] | 时钟没开写寄存器 → 写入无效静默失败，查半天找不到原因 |
| 2 | 所有等待标志位处有**超时退出 + 恢复路径**，不是死等 `while(!flag)` | [M] | 硬件故障/从机掉线时整个系统卡死，看门狗救不了 |
| 3 | **Q9 I2C 恢复序列**：init 先查 `I2C_STAT0_BUSY`，置位切 GPIO 发 9 SCL + STOP 后再复 init | [M] | 热插拔/中途复位 → 从机拉低 SDA 不放 → BUSY 永远 1，纯 deinit+init 清不掉 |
| 4 | **Q8 SPI 切设备**：同一 SPI 挂多从设备（Mode0 Flash + Mode3 OLED）时，**每次 begin() 重配 CPOL/CPHA/波特率** | [M] | Mode 不匹配 → 全错或偶发错；波特率不对 → OLED 高速切到直接丢 |
| 5 | UART/SPI/I2C/CAN 读返回值/错误标志必须检查，失败时进入统一错误恢复 | [M] | 返回值忽略 → 用错误数据继续算，执行机构输出非法控制量 |
| 6 | DMA 与 CPU 共享的缓冲区：CPU 读之前先确认 DMA 完成；转 CPU 写前禁止对应 DMA 通道 | [M] | DMA 和 CPU 同时写 → 数据竞争半更新状态，随机错 |
| 7 | init 幂等：`xxx_init()` 先检查已初始化标志，重复调用不重置运行中状态 | [M] | 网络重传/重试导致二次 init → 缓冲区指针清零，已接收数据丢 |
| 8 | GPIO 复用引脚确认：TX=AF 推挽、RX=AF 上拉或浮空输入、SCL/SDA=AF 开漏+上拉 | [M] | SDA 配成推挽 → I2C 仲裁失败，多主/热插拔总线短路 |
| 9 | `datasheet-lookup` 流程确认：库函数名/寄存器位用头文件 Grep 查过，没凭记忆写 | [M] | `dma_struct_para_init` 实际应为 `dma_single_data_para_struct_init` → 链接错 |
| 10 | 对外写 Flash/外设配置：写前读回比较，相同不写（幂等 + 磨损） | [M] | 每次都写 → Flash 10 万次寿命 1 个月耗完 |

### 场景 3：改了协议结构体（串口/Modbus/CAN/Flash 存储用的 `typedef struct {} xxx_t`）

**先跑脚本**：`code-style-check.ps1 -Checks overflow` → 自动覆盖 Q1（struct 缺 static_assert 字节数）、Q3（宏括号缺）、窄类型相乘扩宽、memcpy 长度

| 顺序 | 检查项 | 方式 | 为什么不能漏 |
|---|---|---|---|
| 1 | **Q1 `_Static_assert(sizeof(...))`**：`typedef struct {} xxx_t;` 后 10 行内必有 `_Static_assert(sizeof(xxx_t) == N)` | [A] | 32 位编译器自动 4 字节对齐 padding → 肉眼算 5 字节实际 8 字节，`memcpy(&pkt,raw,5)` 高 3 字节随机值 |
| 2 | 协议结构体成员顺序：固定大小字段在前，变长/长度描述字段在实际数组前，成员顺序和协议文档一字节不差 | [M] | 顺序错 → 解析全错位，双方结构不同步 → 偶发错且抓不到 |
| 3 | `uint8_t` 类型位宽字段（长度/计数）→ 收到后做范围判断（len ≤ MAX_BUF，index < COUNT） | [M] | 对端发 65535 作为长度 → 写内存越界 HardFault |
| 4 | 跨端多字节整数：显式拼装 `(u16)buf[0]<<8 \| buf[1]`，不直接 cast 指针 | [M] | cast 指针依赖大小端；M0+ 非对齐访问直接 HardFault |
| 5 | `__packed`/`#pragma pack(1)` 结构体成员：读/写用 `memcpy`，不解引用成员指针 | [M] | M0/M0+ 非对齐成员指针解引用直接 HardFault |
| 6 | 尾部长度相关宏（PKT_PAYLOAD_SIZE、CMD_BUF_LEN）：含运算符的宏有**双重括号** `((N+HDR_SIZE+CRC))` | [A] | 宏缺括号 → `SQUARE(a+b)` 展开为 `a+b*a+b`，长度计算完全错 |
| 7 | 关键配置/固件：带 CRC32/CRC16，读入时校验，坏则走三份冗余或默认安全值 | [M] | Flash 位翻转/EMC 干扰读错 → 用错误配置跑系统 → 难排查 |
| 8 | 枚举/魔数/版本号：结构体带 magic 头 + 版本号字段，init 时先判 magic，错就不使用 | [M] | 读了未初始化/擦除了但没写的 Flash 区域 → 全 FF 当有效数据 |
| 9 | 结构体改字段后，Grep 全局：初始化列表、引用成员处都同步（.h→.c 跨文件） | [M] | 加了字段初始化没改 → 新增字段随机值 0/非 0，逻辑异常 |

## 二十、审查流程

1. **先读参考项目** —— 确认已有的函数和风格
2. **逐项检查** —— 按上述清单逐条过
3. **列出问题** —— 发现的问题按严重程度排序
4. **提出修改** —— 给出具体代码修改建议
5. **等用户验证** —— 修改后由用户烧录验证

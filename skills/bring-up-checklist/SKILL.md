# Bring-Up 上电查验清单

新板第一天上电的强制流程。目的：**每一步只验证一件事**，坏板最快定位在哪一层。

## 一、查验顺序（从底到顶，禁止跳跃）

| 序 | 检查项 | 测量方法 | 预期现象 | 结果记录 |
|---|---|---|---|---|
| 1 | 电源轨 | 万用表：3.3V/5V/1.8V 各测试点 | 偏差 <5%，纹波可后续看 | 实测值 |
| 2 | 晶振起振 | 示波器量 XTAL 引脚正弦波；或万用表确认(见注意) | 频率误差 <500ppm（USB 硬门槛） | 实测频率 |
| 3 | 复位 | 拉低 NRST 再释放 | 释放后芯片进入运行 | 波形/现象 |
| 4 | BOOT 配置 | 万用表量 BOOT0/BOOT1 电平 | 用户程序从 Flash 启动 | 电平值 |
| 5 | 调试口 | 串口出 banner / 调试器能识别 ID | banner 一行 | 记录 |
| 6 | 时钟树 | 读 SYSCLK 寄存器或输出 MCO 到引脚 | 与设计频率一致 | 值 |
| 7 | 逐外设点亮 | 每外设最少功能验证（LED 亮/串口回环/I2C 扫描地址） | 外设自检全 PASS | 逐项结果 |

注意：部分晶振用万用表直流档量两脚电压约 VCC/2 可粗判起振，但频率精度必须示波器。

## 二、每步三列铁律

**测量方法 / 预期现象 / 结果记录** 三列缺一不可。禁止凭"感觉芯片在跑"进入下一步。

## 三、芯片系列差异

| 系列 | 差异点 |
|---|---|
| ARM Cortex-M（GD32/STM32，Keil） | 时钟树宏必须核对注释状态（`__SYSTEM_CLOCK_168M_PLL_8M_HXTAL` 等）；USB 项目栈经验下限 ≥2KB（裸机 TinyUSB + -O0 + printf 组合下 1KB 不够，V52.4/SYGPAD V1 两次教训）——仅 ARM+USB 适用，-O2 发布版可评估更低值；建议同时启用栈金丝雀监控 |
| 8051（STC8，Keil C51） | 无调试器时靠串口打印；复位电容/供电纹波敏感 |
| ESP32（ESP-IDF） | 用 `idf.py monitor` 看 boot 日志；40MHz 晶振精度影响 WiFi/蓝牙 |

系列规则细节见 chip-rules 技能 L2 层。

## 四、可裁剪原则

- 清单按板子裁剪：没有的项**划掉并注明"本板无"**，不要照抄全项
- 有电池的板加"掉电保持检查"；有以太网的板加"PHY ID 读取"

## 五、与现有技能联动

| 技能 | 用途 |
|---|---|
| hardware-detection | 探测调试器连接/芯片 ID/电压（自动执行第 1/5 步） |
| schematic-reading | 核对电源轨/复位/BOOT 接线是否符合原理图 |
| peripheral-test-template | 第 7 步外设自检的实施模板 |
| board-config | 记录板级参数供后续驱动使用 |

## 执行位置（四步准备流程）

- 四步准备"第二步 硬件平台评估"之后、**V0 首跑之前**执行上电查验
- 查验结果写进项目的 Hardware 文档（六目录 Hardware\ 层），每一项标 通过/失败/未测
- 任一项失败：先归因（电源问题/焊接问题/原理图错误），未归因前禁止继续下一层

# 测试报告生成

## 适用场景

- 用户跑完 peripheral-test-template 的自检，需要生成报告
- 用户跑完单元测试（Unity），需要汇总结果
- 项目交付需要正式测试文档
- 用户要求"把测试结果整理一下"
- 回归测试后需要对比前后结果

<!-- 层级归属：L0/L2 结果闭环，依据 embedded-dev-rules §4.6 驱动验证四层标准 -->
> **L0/L2 结果闭环（依据 embedded-dev-rules §4.6）**：本技能汇总 L0（单元测试）与 L2（真机自检 + 压力）结果入缺陷台账，回归基线只增不减。生成报告时机 = L0 跑完 / L2 自检通过后、版本交付前。

## 报告类型

### 1. 硬件自检报告

来源：peripheral-test-template 的串口输出
格式：

```markdown
# 硬件自检报告

**项目**: {项目名称}
**硬件版本**: PCB Rev {x.x}
**固件版本**: v{x.y.z}
**测试日期**: {YYYY-MM-DD}
**测试人员**: {姓名}
**测试环境**: 室温 {xx}°C，供电 {x.x}V

## 测试总结

| 类别 | 通过 | 失败 | 跳过 | 通过率 |
|------|------|------|------|--------|
| GPIO | 4/4 | 0 | 0 | 100% |
| UART | 2/2 | 0 | 0 | 100% |
| I2C | 1/2 | 1 | 0 | 50% |
| SPI | 1/1 | 0 | 0 | 100% |
| ADC | 3/3 | 0 | 0 | 100% |
| **总计** | **11/12** | **1** | **0** | **91.7%** |

## 详细结果

### GPIO 测试

| # | 测试项 | 预期 | 实际 | 结果 |
|---|--------|------|------|------|
| 1 | LED1 点亮 | PC13 输出低 | PC13=0, LED亮 | ✅ PASS |
| 2 | LED1 熄灭 | PC13 输出高 | PC13=1, LED灭 | ✅ PASS |
| 3 | KEY1 读取 | 按下=低 | 按下读到0 | ✅ PASS |
| 4 | KEY2 读取 | 按下=低 | 按下读到0 | ✅ PASS |

### I2C 测试

| # | 测试项 | 预期 | 实际 | 结果 |
|---|--------|------|------|------|
| 1 | BMP280 连接 (0x76) | WHO_AM_I=0x58 | 读到 0x58 | ✅ PASS |
| 2 | MPU6050 连接 (0x68) | WHO_AM_I=0x68 | 无 ACK | ❌ FAIL |

### 失败项分析

**I2C-2: MPU6050 无响应**
- 现象：发送地址 0x68 后无 ACK
- 可能原因：
  1. MPU6050 未焊接或虚焊
  2. AD0 引脚悬空导致地址不确定
  3. 供电引脚未连接
- 建议：检查 U3 焊接，确认 AD0 接地（地址 0x68）

## 结论

{通过/有条件通过/不通过}

{如有条件通过，说明哪些项需要复测}
```

```
Expected: -1 (拒绝降级)
Actual:   0 (允许)
File: test/test_ota_manager.c:87
```

**分析**: version_compare() 在 MAJOR 相同时未正确比较 MINOR

```

```

**分析**: CRC 校验在 image_size=0 时被跳过

## 从串口日志自动提取

当用户提供自检的串口输出时，解析规则：

```
[SELFTEST] GPIO_LED1 ... PASS
[SELFTEST] I2C_BMP280 ... PASS
[SELFTEST] I2C_MPU6050 ... FAIL (no ACK)
[SELFTEST] SPI_FLASH ... PASS
[SELFTEST] ADC_VBAT ... PASS (3.72V)
[SELFTEST] === SUMMARY: 4/5 PASS, 1 FAIL ===
```

解析为结构化数据后填入报告模板。

## 输出格式选择

| 场景 | 格式 | 工具 |
|------|------|------|
| 内部记录/存档 | Markdown (.md) | 直接生成 |
| 正式交付文档 | Word (.docx) | docx 技能 |

## 与现有技能联动

- **peripheral-test-template** → 提供自检原始数据
- **embedded-unit-test** → 提供单元测试输出
- **serial-debug** → 捕获串口测试日志
- **memory-analysis** → 提供资源占用数据
- **docx / pdf** → 格式化输出
- **git-workflow** → 关联版本号和 commit

## Pitfalls

- 测试报告必须基于实际数据，不要编造测试结果
- 失败项必须给出分析和下一步建议，不能只写 FAIL
- 注明测试条件（温度、电压、硬件版本），否则结果不可复现
- 压力测试要记录具体失败时刻和现象，不能只写"有问题"
- 通过率计算要包含跳过的项（标注为 SKIP，不计入通过）
- 正式报告需要测试人员和日期，不能遗漏

## Verification

- 报告中每个 PASS/FAIL 都有对应的原始数据支撑
- 总数统计正确（通过+失败+跳过 = 总用例数）
- 失败项都有原因分析
- 版本号和日期与实际一致

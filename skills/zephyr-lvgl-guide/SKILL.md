# Zephyr + LVGL 项目防坑指南

> 基于 GD32F407VE + ST7789(172×320) + CST816T 手表项目的实战教训（V2.x 系列）。原则通用，数值为参考起点，落地以实际芯片资源与 LVGL 版本为准。

## 适用场景

- 新建 Zephyr + LVGL 工程（west + CONFIG_LVGL 模块）
- 维护现有 Zephyr + LVGL UI（加页面/壁纸/字体/功能）
- 排查：黑屏、界面定格、触摸失灵、随机死机、Flash/RAM 超限

## 一、内存三兄弟（黑屏/死机第一嫌疑）

| 项 | Kconfig/配置 | 参考值 | 坑 |
|---|---|---|---|
| 渲染线程栈 | `CONFIG_LV_Z_LVGL_WORKQUEUE_STACK_SIZE` | **16384** | 默认 4096 会被整屏壁纸/复杂 UI 渲染调用链击穿，症状=**静默全黑**（固件活着、无日志、无 fault） |
| LVGL 内存池 | `CONFIG_LV_Z_MEM_POOL_SIZE` | 40~48KB | 池耗尽=`LV_ASSERT_MALLOC` 死循环（界面定格+触摸失灵+无日志）；加对象/字形缓存后必须核对余量 |
| 大图瞬态缓冲 | 壁纸/大图格式选择 | 见下 | 解码缓冲是临时大内存，选格式就是选内存/体积 |

**格式取舍**（以 172×320 为例）：
- RGB565 裸数据：约 110KB，渲染免转换，但 Flash 占满
- RGB565_SWAPPED：字节预交换，与 `CONFIG_LV_COLOR_16_SWAP=y` 的原生格式一致，渲染最省事
- I8 索引色：约 56KB，解码需 688B 部分缓冲，兼容性需实测（模拟器正常≠板子正常）
- LZ4：最小但解码缓冲大、板级兼容性差

## 二、显示链路四件套（黑屏排查顺序）

1. **渲染线程栈**（见上，最先查）
2. **字节序**：`CONFIG_LV_COLOR_16_SWAP` 必须与面板 RGB565 字节序一致，图片格式也要匹配——颜色错乱/灰变黑先看这
3. **面板上电时序**：显示设备树节点加 `ready-time-ms = <250>`（等面板 VCI 稳定再初始化，防冷启动黑屏）。**注意该字段是 uint8_t（0-255），写 300 会被截断成 44ms**，等于没延时
4. **面板硬件复位**：MCU 复位瞬间若 SPI 传送到一半，面板会卡死在写模式，只有硬件复位/断电能救回——症状=按复位键随机黑屏（约 50%），冷启动正常。mipi_dbi 配 `reset-gpios`（低有效）可硬件复位恢复。**坑：脉冲不一定安全**——本案例 PD6 拉低 6ms 会把 USB 串口链路打死（每次启动串口即死），且该引脚未必物理连到面板 RST；最终方案=飞线 PD6→面板 RST 稳定复位参考 + 固件**移除** reset-gpios（驱动回退 SPI 软件复位，串口才存活）

**全黑排查顺序口诀：栈 → 字节序 → 上电时序 → 面板复位 → 硬件（FPC 排线）**

## 三、Flash 体积控制（LVGL 9 很能吃）

**裁剪四步法**（V2.3.x 实战：96.85% → 47.16%，省 254KB）：
1. **量化**：`arm-zephyr-eabi-size zephyr.elf` 看段；从 map 筛 >4KB 符号按大小排序，前 10 名即优化目标
2. **分类**：图片/字体（资源）用删除/压缩/裁字符集；库功能用 Kconfig 关（如 `CONFIG_LV_USE_LZ4=n` 省约 126KB）；未用组件用 `CONFIG_LV_USE_*=n` 关（本案例关 25 个组件）
3. **排序**：大头优先、纯开关（低风险）先做、资源后做；**注意依赖**——slider 依赖 bar，`CONFIG_LV_USE_BAR` 不能关（否则编译报 `LV_BAR_ORIENTATION` 未定义）
4. **验证**：每批改动重建看 `FLASH: xxx B` 变化 + 上板确认 UI；可合批但保留单独回退能力

- 中文字库**必须裁剪**：`lv_font_conv --symbols "用到哪些字就写哪些字"`，33 字约 73KB，全量字符集直接几百 KB
- 新增界面文字前先核对字在字库内，缺字显示方框；需加字就重新生成字库
- 图片选压缩格式（LZ4/I8 vs 裸 RGB565），体积/内存/兼容性三角取舍
- Kconfig 按需裁剪（如 `CONFIG_LV_BUILD_EXTRAS` 等未用功能关掉）
- 大数字字体按需裁字符集：`lv_font_conv --font Montserrat-Medium.ttf --size 48 --range 0x30-0x39,0x3A`（仅 0-9 冒号），90KB→19KB；再用 `CONFIG_LV_FONT_MONTSERRAT_48=n` 关掉内置全字符字体
- 参考：172×320 手表全套（去壁纸 + 裁剪后）约 47% Flash / 78% RAM；裁剪前（UI+壁纸+全字体）约 96%

## 四、版本匹配

- LVGL 9.x 与 8.x **API 不兼容**（符号、API 改名、部分 symbol 移除，如 `LV_SYMBOL_HEART`），别照抄 8.x 教程/代码
- Zephyr 模块的 LVGL 版本由 west manifest 锁定，升级 Zephyr 时 LVGL 可能跟着升，UI 代码要做回归
- 触摸坐标：面板分辨率 vs LVGL 分辨率别混（本案例 172×320 identity 直通，无需偏移/镜像）

## 五、开发流程

1. **模拟器先行**：同一份 UI 代码（不依赖 Zephyr）跑 PC 模拟器（SDL）验证逻辑/布局，过滤 80% 问题。但模拟器栈大、无 SPI 时序，**模拟器正常 ≠ 板子正常**，驱动/时序/内存类改动必须板级验证
2. **改动后核对**：改 UI/壁纸/字体后 → 先查渲染栈余量 → 再板级验证显示 → 不要只看"能编译能跑"
3. **监控常开**：`CONFIG_THREAD_ANALYZER` + 周期打印各线程栈峰值；LVGL 池余量周期打印——开发期暴露问题，别等烧录后黑屏。**坑：921600 高波特率下 thread_analyzer 大段打印会 stall USB 串口（CH340），串口约 30-40s 后静默**，监控打印需控制频率/篇幅
4. **固件归档**：每个验证通过的版本保存 `Firmware_Build/<版本号>/`（bin/hex/elf + src/assets/config 快照），版本号三处一致（代码/文件名/日志）

## 六、改动后检查清单

- [ ] 渲染线程栈 ≥16KB，且 thread_analyzer 峰值余量 ≥30%
- [ ] LVGL 池余量充足（加对象/字形后复测）
- [ ] 字节序与面板匹配（换图片格式/换面板必查）
- [ ] `ready-time-ms` 在 0-255 有效范围
- [ ] mipi_dbi `reset-gpios`：先实测脉冲不干扰串口/其他外设，且确认引脚物理连到面板 RST；否则移除（回退 SW_RESET）
- [ ] 中文字全部在裁剪字库内（无方框）
- [ ] Flash/RAM 占用复核，超 95% 预警
- [ ] 模拟器 + 板级双验证；断电冷启动 + 复位键两场景都测

# 调试日志规范

本技能定义跨项目的调试日志标准。目标：让任何一次的现场日志都能回答"哪个版本、什么时刻、哪个模块、发生了什么、如何复现"。

## 一、日志格式标准（新代码必须遵守）

统一为四要素格式：

```
[V<版本>][<毫秒时间戳>][<模块TAG>] <消息>
```

- 示例：`[V1.2][001234][USB] SETUP rx: 0x80 0x06 0x0100 len=64`
- MicroLIB 注意：`%lu` 不可用，长整型用 `%u` + `(unsigned int)` 强转（历史教训：%lu 会卡死）
- 时间戳用 ms 级（DWT 或 systick），1ms 即可，不需要 RTC 日期
- TAG 用固定大写缩写：USB / UART / SPI / ENET / KEY / ADC / MAIN / ISR

## 二、故障现场三件套（死机/异常时必须全有）

1. **寄存器快照**：外设关键寄存器 + 堆栈指针（ARM 还有 CFSR/HFSR）
2. **调用栈**：PC/LR 地址（配合 map 文件反查函数，已有 `[FAULT] PC=... LR=...` 范例）
3. **复现步骤**：一段文字描述"做什么操作、第几步死的"

三件套缺一，问题排查成本翻倍。

## 三、中断安全红线

- **ISR 内禁止 printf**（阻塞 + 重入，曾导致变量被嵌套调用覆盖的假象）
- ISR 内记录用**环形缓冲**（计数器/事件数组），主循环统一转储
- 诊断打印默认关闭（`XXX_DIAG_EN=0` 开关），需要时再开

## 四、时序敏感系统的额外规则（USB/高速总线专用）

- 总线忙时（枚举、握手窗口期）禁止批量打印：printf 阻塞 2 秒会杀死 2ms 的 SET_ADDRESS 窗口
- 诊断转储只在"总线安静（ISR 计数 N 秒无变化）"时输出
- 宁可少打，不可打乱时序

## 五、日志文件管理

- 命名：`usn_<模块>_<日期>.md` 或 `.txt`，放项目 `Logs\` 目录
- 版本三件套：固件内 printf 版本号 = 产物文件名 = 日志文件名（三处一致）
- 事后归入 `Firmware_Build\Vxx\` 归档

## 六、与其它技能联动

| 技能 | 关系 |
|---|---|
| log-analysis | 格式规范后可做结构化解析 |
| hardfault-diagnosis | 三件套之二的规范来源 |
| release-notes | 日志 → 版本说明的素材链 |

## 执行规则

- 老项目日志不追改（只规范新代码），避免无意义返工
- 新项目第一次写 UART 输出前，先按本技能定 TAG 表

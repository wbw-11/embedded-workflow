# 指针与数组等价换算：下标与偏移互化

## R — 原文 (Reading)

> "在计算数组元素a[i]的值时，C语言实际上先将其转换为*(a+i)的形式，然后再进行求值，因此在程序中这两种形式是等价的。……简而言之，一个通过数组和下标实现的表达式可等价地通过指针和偏移量实现。"（第5章 §5.3）
>
> "指针是一个变量，因此，在C语言中，语句pa=a和pa++都是合法的。但数组名不是变量，因此，类似于a=pa和a++形式的语句是非法的。"（第5章 §5.3）
>
> "无论数组a中元素的类型或数组长度是什么……'指针加1'就意味着，pa+1指向pa所指向的对象的下一个对象。"（第5章 §5.3）
>
> — B. W. Kernighan & D. M. Ritchie, 第5章 指针与数组

## I — 方法论骨架 (Interpretation)

C 语言把"数组名"定义为**首元素地址的常量值**，因此下标天然可展开为指针算术：

- `a[i]` 定义为 `*(a+i)`，`&a[i]` 定义为 `a+i` —— 下标和地址偏移是同一件事的两种写法；
- 数组名 `a` 是常量地址，**不是变量**：`pa = a` 合法、`a = pa` 与 `a++` 非法；想移动就得用指针变量；
- 指针算术以"对象"为单位（`pa+1` 是下一个对象，不是加一个字节），对任何类型成立；
- 把数组传给函数时，实参退化为该数组首元素的地址，形参 `char s[]` 与 `char *s` 等价。

这套换算让你在"读代码"与"写代码"两个方向都能自由切换，并一眼识别出 `a++` 这类非法写法的原因。

## A1 — 书中的应用 (Past Application)

### 案例 1: strlen 的指针版
- **问题**: 计算字符串长度，第 1 版用下标 `for (n=0; s[n]!='\0'; n++)`，需要等价但更"指针味"的写法。
- **方法论的使用**: 作者把形参看成指针，用 `for (n=0; *s != '\0'; s++) n++;`，在函数内把形参 `s` 当指针移动。
- **结论**: 形参 `char *s` 就是指针变量，可以自增；`a[i]` 与 `*(a+i)` 在此完全互换。
- **结果**: 生成第二个 strlen 版本，证明"数组参数即指针"（第5章 §5.3）。

### 案例 2: 文字行排序 lineptr
- **问题**: 对长度不一的文本行排序，直接搬动文本行本身会带来巨大的存储管理与开销。
- **方法论的使用**: 把所有行放进长字符数组，用"指针数组" `lineptr[]` 指向各行；排序时只交换指针。
- **结论**: 指针是可变长度数据的高效表示——`&a[i]≡a+i` 让指针数组天然可像普通数组一样下标访问。
- **结果**: 消除了"移动文本行本身"的两个孪生问题（存储管理与开销）（第5章 §5.6）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. debug 一段报"Segmentation fault / 结果错乱"且涉及数组遍历或下标访问的 C 代码；
2. 写嵌入式驱动时用指针遍历缓冲区/寄存器数组，不确定 `p++` 与 `a[i]` 哪个合法、边界在哪；
3. 阅读别人代码时遇到 `*(a+i)`、`pa[i]`、`a+1` 等价写法，需要翻译成下标或 vice versa；
4. 定义函数形参时纠结用 `char s[]` 还是 `char *s`，担心二者不等价；
5. 被编译器报 `lvalue required` 在 `a++`/`a = pa` 处，想弄清数组名到底是不是变量。

### 语言信号 (用户的话里出现这些就应激活)

- "为什么 a[i] 和 *(a+i) 一样？"
- "数组名能自增吗？a++ 为什么报错？"
- "形参 char s[] 和 char *s 有区别吗？"
- "指针怎么遍历数组 / 怎么算便宜 offset？"
- "pointer arithmetic / array name vs pointer / subscript vs offset"

### 与相邻 skill 的区分

- 与 `call-by-value-pointer` 的区别: 它管"函数参数怎么写才能改实参"（输入输出的方向），本 skill 管"下标和地址怎么互换"（表达式等价换算），二维正交。
- 与 `undefined-behavior` 的区别: 它管越界/副作用等"什么行为不可依赖"，本 skill 管合法写法本身如何换算；越界判定可作为其输入。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别对象是"数组名"还是"指针变量"**
   - 完成标准: 给出对象定义出处（声明语句/参数表），并说明它能否出现在赋值/自增左值位。
   - 判停条件: 若对象同时在多个作用域被引用，先确认最近声明。

2. **🔴 CHECKPOINT · 确认识别结果**
   - 完成标准: 向用户复述"对象 X 是数组名（不可自增/赋值）/指针变量（可自增）"及依据（声明出处）；用户确认后才进入换算，不要凭 agent 自决跳步。
   - 判停条件: 若对象声明来源不唯一或用户对归类有异议，回到步骤 1 补齐声明出处再继续。

3. **把表达式换算到同构形式**
   - 完成标准: 将 `a[i]` ↔ `*(a+i)`、`&a[i]` ↔ `a+i`、`pa[i]` ↔ `*(pa+i)` 逐项展开，说明每一处换算的对应关系。
   - 判停条件: 若表达式涉及多维数组，按"外层是数组、内层算术按对象单元"逐维展开后再汇总。

4. **🛑 STOP · 边界风险确认**
   - 完成标准: 检查结论涉及越界/负下标/边界外引用时，暂停并明确告知用户"该写法语法合法但引用边界外对象非法（未定义行为）"，由用户决定是否仍要该写法；绝不静默给出"应该能跑"的结论。
   - 判停条件: 用户要求保留越界写法 → 明确标注风险并建议改写；否则输出安全改写版。

5. **检查合法性并给结论**
   - 完成标准: 明确指出哪些写法非法（`a=pa`、`a++`）、哪些合法但有越界风险（`a[负下标]` 语法合法但边界外引用非法），给出改写建议。

### 失败模式速查（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 用户对"数组名 vs 指针"归类有异议 | 回到步骤 1 补齐声明出处，用 `&a[0]` 与 `a` 的值等价性佐证 | 给出两种归类下的等价写法对照表，请用户按语义选 |

| 表达式含多维数组换算混乱 | 按"外层数组、内层对象单元"逐维展开 | 降维：先转一维指针等价式再逐层代回 |
| 用户坚持越界/负下标写法 | 明确标注"边界外引用非法=未定义行为" | 若必须保留，建议改用偏移量 + 长度参数的安全封装 |

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户问的是"数组能不能整体赋值/比较"这类结构语义问题（那是 data-organization 的 struct/数组对比范畴）；
- 用户需要的是"结构体内存布局"而非下标换算；
- 对象是 C++ 的 `std::array`/引用（规则不同，本书为 C 语义）。

### 作者在书中警告的失败模式

- "引用数组边界之外的对象是非法的"——`p[-1]/p[-2]` 语法合法但与 `p[0]` 之前对象的关系仅当确信存在才成立（第5章 §5.4）；
- "数组名不是变量"——对数组名做 `a=pa`、`a++` 是编译期即报的常见新手错。

### 作者的盲点 / 时代局限

- 本书以 16/32 位机器与 K&R/ANSI 契约为准；现代 C17 引入了可变长数组等语义，指针算术精神不变但边界工具（如 `_Generic`、泛型 `offsetof`）未覆盖。
- 没有系统讨论指针安全性工具（AddressSanitizer/静态分析），越界多在运行期才暴露。

### 容易混淆的邻近方法论

- Lvalue 与右值概念（数组名是右值式常量地址，不是左值）；
- `data-organization` 中"结构大小≠成员之和"——那是对齐空穴问题，不是指针换算问题。

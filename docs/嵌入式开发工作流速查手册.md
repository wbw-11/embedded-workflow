## 1. 需求阶段

**入口**：需求为零散输入（聊天/截图/语音/旧说明书）时，**先过 requirement-extraction，不得直接进硬件评估**。

| 你做 | 助手用 |
|------|--------|
| 提供原始需求/聊天记录/截图 | 技能：`requirement-extraction`（REQ 编号 + P0-P2 + 四要素逐行带证据 + 冲突/缺漏表） |
| 确认需求清单 | 变更时助手自动带出回归用例三栏表（REQ→模块→L0/L2 用例） |

## 2. 新项目启动（四步准备）

**红线**：写首行代码前必须四步准备文档书面产出，你明确 OK 后才准写码（判定标准见 embedded-dev-rules）。

| 步骤 | 你做 | 助手用 |
|------|------|--------|
| ① 需求分析 | 确认需求清单 | requirement-extraction、writing-plans |
| ② 硬件评估 | 提供原理图/接线；确认引脚、时钟源 | schematic-reading、datasheet-lookup、pin-check、hardware-detection、board-config |
| ③ 软件架构 | 确认 V0→Vn 梯度 | software-design-doc、writing-plans |
| ④ 工具链 | 开张三连：git init、装 pre-commit 钩子、复制缺陷台账 | 脚本：install-precommit；技能：git-workflow、project-init |
| 开工确认 | 回复 OK/确认 | — |

**承接脚本**：detect-chip（确认型号，不匹配立即告知）→ switch-board（选板记录跨会话共享）→ new-board-config（新建板配置）→ pin-check（引脚册）。

## 5. 代码审查与自检（烧录前强制）

| 你做 | 助手自动执行 |
|------|-------------|
| 审查前确认是否跳过（未审须提示） | 技能 embedded-code-review（22 类 90+ 项：ISR 安全/缓冲区/溢出/volatile/GPIO/内存/低功耗） |
| — | 脚本 code-style-check（缩进/行宽/命名/溢出/防御 D1D2 自动检测，警告清零） |
| — | warning-db（编译警告匹配），log-analysis（编译/运行日志解析） |
| — | impact-analyze（改 .h/签名后按高/中/低列影响文件） |
| — | 主机端单元测试 embedded-unit-test（Unity+CMock，0 硬件成本） |

**提交门禁**：git commit 时 pre-commit 钩子自动拦截 P0 溢出隐患 + 无 BOM 中文 ps1；逃生 `git commit --no-verify` 须注明原因。

## 6. 编译烧录

| 你做 | 助手自动执行（按项目类型自动识别） |
|------|-----------------------------------|
| 一次性配置（Keil 调试器 CMSIS-DAP、波特率、ccache） | 仅首次，你手动 |
| — | **日常编译**：build-all / dev-flow（自动识别 ESP-IDF / Keil ARM / C51） |
| — | **增量编译纪律**：先 `-b`（日志含 compiling）+ 核对 axf 时间戳 → 再 `-f` 烧录，禁止直接 -f |
| 烧录点头（Y/N/S，每轮必确认） | safe-flash 5 重验证：扫描串口→识别芯片→与 CURRENT_BOARD 匹配→你确认→执行烧录 |
| — | dev-flow 一键闭环：识别→增量编译→时间戳门禁→版本门禁→烧录→产物特征核验→Firmware_Build 归档 |
| — | Keil：keil-auto-flash；ESP32：esp-idf-build / esp-burn / esp-monitor / esp-erase-flash |

**烧录门禁三件套（任何芯片强制）**：静态 code-style-check + 人工快查（安全/并发/缓冲区）+ 产物时间戳比源码新。

## 7. 调试验证

| 现象 | 你用 | 助手用 |
|------|------|--------|
| 串口查看/发送 | 反馈乱码/无回显 | 脚本 serial-debug、capture_serial_reset、watch-board；技能 serial-debug |
| 能发不能收/协议异常 | — | 技能 protocol-analysis（I2C/SPI/UART/CAN 抓包分析）、log-analysis |
| ARM Keil HardFault | 提供崩溃现象 | hardfault-diagnosis（捕获寄存器→反汇编定位） |
| ESP32 Panic/Guru Meditation | 提供 backtrace | esp32-panic-diagnosis、live-debug-workflow（OpenOCD+GDB 断点/单步） |
| 内存异常/耗损 | — | memory-analysis（Code/RO/RW/ZI 占比）、memory-leak-detection（ESP32 heap 监控） |
| 死机/黑屏/随机复位 | — | 先查栈（渲染/深调用线程栈 ≥16KB）；hardfault-diagnosis |
| 无线连不上/断连 | — | wireless-sniffer（BLE/WiFi 抓包 Wireshark）、rf-verification |

**自检类**：peripheral-test-template（串口收发/GPIO/I2C 扫描/ADC 读取）、电脑桌面自动化可用 MCP mcp_Computer_Use 协助人机验证。
